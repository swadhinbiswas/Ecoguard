# Render Deployment

[Render](https://render.com) provides a PaaS for deploying Eco-Guard with a managed PostgreSQL database. The `render.yaml` file defines the infrastructure as code.

## render.yaml Explanation

```yaml
services:
  - type: web
    name: eco-guard
    env: python
    buildCommand: pip install -r requirements.txt && cd frontend && npm install && npm run build && cd ..
    startCommand: uvicorn src.main:app --host 0.0.0.0 --port $PORT
    envVars:
      - key: PYTHON_VERSION
        value: "3.12"
      - key: ENVIRONMENT
        value: production
      - key: DATABASE_URL
        fromDatabase:
          name: eco-guard-db
          property: connectionString
      - key: JWT_SECRET
        generateValue: true
      - key: ADMIN_USERNAME
        sync: false
      - key: ADMIN_PASSWORD
        sync: false

databases:
  - name: eco-guard-db
    databaseName: ecoguard
    plan: free
```

### Service Definition

| Field | Value | Description |
|-------|-------|-------------|
| `type` | `web` | HTTP service |
| `name` | `eco-guard` | Service name in Render dashboard |
| `env` | `python` | Runtime environment |
| `buildCommand` | (see below) | Commands run during build |
| `startCommand` | `uvicorn ...` | Command to start the server |

### Build Command Breakdown

```bash
pip install -r requirements.txt    # Install Python dependencies
cd frontend && npm install && npm run build && cd ..  # Build Vue.js frontend
```

The frontend build produces static files in `frontend/dist/` which Eco-Guard serves as its dashboard SPA.

### Start Command

```bash
uvicorn src.main:app --host 0.0.0.0 --port $PORT
```

Render injects the `$PORT` environment variable dynamically (typically 10000).

## Free Tier Limitations

Render's free tier has these constraints:

| Constraint | Free Tier Limit | Impact on Eco-Guard |
|------------|----------------|---------------------|
| **RAM** | 512 MB | May not fit large GGUF models |
| **CPU** | Shared | Slower inference |
| **Disk** | Ephemeral | Models must be re-downloaded on each deploy or use external storage |
| **Web service sleep** | After 15 min inactivity | Cold start latency (~30–60 seconds) |
| **Database** | 1 GB storage, expires after 90 days | Suitable for development only |
| **Build minutes** | 500 min/month | Adequate for occasional deploys |

### Working Around Model Storage

Since Render's filesystem is ephemeral, models need to be either:

1. **Downloaded at build time** (add to `buildCommand`):
   ```bash
   mkdir -p models && curl -L -o models/model.gguf https://huggingface.co/.../model.gguf
   ```

2. **Stored on external volume** (Render Disk, paid feature):
   Create a disk and mount it at `/app/models`.

3. **Use a remote backend** (vLLM, Ollama) and point `BACKEND_URL` to that service:

   ```env
   BACKEND=ollama
   BACKEND_URL=https://your-ollama-service.com
   ```

## Database Provisioning

Render automatically provisions a PostgreSQL database:

```yaml
databases:
  - name: eco-guard-db
    databaseName: ecoguard
    plan: free
```

The `DATABASE_URL` is injected via `fromDatabase`:

```yaml
- key: DATABASE_URL
  fromDatabase:
    name: eco-guard-db
    property: connectionString
```

Render generates a random connection string with strong credentials. Note that the Render connection URL uses `postgres://` but Eco-Guard needs `postgresql+asyncpg://`. The `init_db()` function handles this conversion automatically (the URL is passed to SQLAlchemy which accepts both prefixes), but if you encounter issues, the database module supports the standard format.

## Environment Variables

Configure additional variables after initial deployment:

### Required for Production

```env
JWT_SECRET=<auto-generated-by-render>
ENVIRONMENT=production
```

### Model Configuration

```env
MODEL_PATH=./models/tinyllama.gguf
MODEL_N_CTX=2048
MODEL_N_THREADS=2         # Lower for shared CPU
MAX_CONCURRENT_INFERENCE=2 # Lower for limited resources
```

### Using a Remote Backend

```env
BACKEND=openai
BACKEND_URL=https://api.openai.com
BACKEND_API_KEY=sk-...
BACKEND_MODEL=gpt-3.5-turbo-instruct
```

### Security

```env
AUTH_ENABLED=true
ADMIN_USERNAME=admin
ADMIN_PASSWORD=<your-secure-password>
CORS_ORIGINS=["https://eco-guard.onrender.com"]
```

## Deploying

### Option 1: Blueprint (Infrastructure as Code)

1. Push your repository to GitHub/GitLab
2. In Render dashboard, click **New → Blueprint**
3. Connect your repository
4. Render reads `render.yaml` and creates all resources automatically

### Option 2: Manual Web Service

1. In Render dashboard, click **New → Web Service**
2. Connect your repository
3. Set:
   - **Name:** `eco-guard`
   - **Environment:** `Python 3`
   - **Build Command:** `pip install -r requirements.txt && cd frontend && npm install && npm run build && cd ..`
   - **Start Command:** `uvicorn src.main:app --host 0.0.0.0 --port $PORT`
4. Add a PostgreSQL database from the dashboard
5. Add environment variables

### Verify Deployment

```bash
# Check health (use your Render URL)
curl https://eco-guard.onrender.com/api/v1/health

# Check database connectivity
curl https://eco-guard.onrender.com/api/v1/health | jq .checks.database

# Test inference
curl -X POST https://eco-guard.onrender.com/api/v1/predict \
  -H "Content-Type: application/json" \
  -H "X-API-Key: eco-guard-dev-key" \
  -d '{"prompt":"Hello world","max_tokens":10}'
```

## Cold Start Considerations

Free tier web services sleep after 15 minutes of inactivity. The first request after sleep takes 30–60 seconds to start. Mitigations:

1. **Use a cron job** to ping the health endpoint every 10 minutes:
   ```bash
   # Add to cron on another server or use a free cron service
   */10 * * * * curl -s https://eco-guard.onrender.com/api/v1/health > /dev/null
   ```

2. **Upgrade to a paid plan** ($7/month for the Starter plan) to eliminate sleep

3. **Use Vercel for the frontend** and keep Render only for the API

## Limitations

- **Ephemeral disk**: Models must be downloaded at build time or stored on a Render Disk
- **Single region**: Free tier is limited to `oregon` (US West)
- **Limited resources**: 512 MB RAM may not accommodate larger models
- **No GPU**: CPU-only inference; use a remote backend for GPU inference
- **90-day database expiry**: Free PostgreSQL databases are deleted after 90 days; upgrade to a paid database for persistence
